# 人物档案首版实现

本文记录人物档案 MVP 的交付范围、与原型不同的产品选择，以及维护边界。数据来源和构建命令见[人物索引构建与验收](character-index-build.md)，原始方案见[产品设计](character-archive-design.md)。

## 已实现范围

- 主导航第二项为人物档案，支持姓名、英文名、真名别名和形态名称搜索，以及类型、职业、阵营、星级筛选和排序。
- 人物详情包含形态切换、分层档案、立绘画廊与全屏查看、按篇章分组的出场和每幕台词节选。
- 从节选打开播放器时验证脚本位置；回放默认不写入观看进度，明确确认“继续观看”后才转为正常观看。
- 列表搜索、筛选与滚动位置，以及详情形态和章节展开状态，在打开回放再返回后保留。

## 产品选择

### 文本可离线阅读，图片按需加载

首版把索引和全部人物文本随应用发布，不依赖尚未部署的远程 manifest 服务。详情按需解析，最多保留 12 份详情读取缓存。图片通过现有共享缓存加载，不归入某篇剧情的缓存目录；清理单篇剧情不会删除内置档案文本。无图和下载失败均显示文字占位。

2026-11-10 快照包含 1,055 位人物、440 个干员形态和 2,061 篇剧情的扫描记录。数字来自构建报告，不能解释为完整识别了剧情中的所有人物。界面使用“已识别出场”表述；零出场人物仍可阅读资料。

### 不用观看断点推断已读

项目的观看断点不是完整的已读记录。首版所有台词节选和深层档案默认折叠，可逐幕主动显示；关闭剧透保护需要确认，不据此永久解除其他浏览会话的保护。NPC 简介也按深层内容处理，因为简介本身可能透露身份或结局。

### 不猜测台词位置或分支

索引保存原始脚本字节的 SHA-256、从 0 开始的指令序号和从 1 开始的原始行号。原始字节哈希与正常观看断点的指令指纹不同，不可混用。

哈希一致时仍检查目标指令的说话人与文本。脚本变化时，只有原始行能消除重复，或说话人与文本组合唯一，才自动重新定位；内容不明确时从头观看并提示。播放器按第一个可用选项重建分支；不能到达的台词会提示并回到开头，不宣称精确还原另一条分支。

档案模式统一拦截进度写入，因此正常推进、跳转、进入后台、播放结束和退出均不会替换或清除原断点。“继续观看”会先说明将替换本篇断点，用户确认后才保存当前位置。退出回放使用播放器左上角返回按钮或系统返回。

### 保留人物身份与资源路径的区别

同体异格仅依据官方 patch 关系或人工表合并。别名只用于已核实的身份映射；不按名字子串、最近似名称或台词热度自动归并。

NPC 人物 ID 仍是名称编码，但资源文件名改为该 ID 的完整 SHA-256。这样避免 Flutter 再次转义百分号后超过 Windows 文件名长度限制；客户端与构建器共用同一函数。界面必须使用索引里的 `detailFile`，不能自己拼接 ID 路径。

## 后续范围与限制

- 当前整体具名台词识别率为 71.88%，高频称呼识别率为 94.30%；未识别部分仍保留在构建报告中，不生成无资料的占位人物卡。
- 已验证的图片 URL 不保证永久可用；头像和基础立绘已检查，但未把剧情脚本内所有干员限定形象自动归入画廊。
- 暂未实现远程档案更新、人物收藏与链接、完整图片离线包、拼音搜索、皮肤/表情画廊、全部台词页，以及播放器内点击说话人跳转人物页。
- 人物 ID 若因 NPC 更名而改变，未来加入收藏或外部链接时必须先提供迁移映射。
- 不把构建目录直接当成线上数据服务；更新内置资源前必须完成数据验收、打包与测试。

组件测试覆盖 320px 与 1280px、两倍文字缩放、组合筛选、三形态资料、失败重试、台词定位降级、非默认分支，以及回放期间不写进度和确认后才保存。真实资源测试读取随包数据，核对阿米娅三个形态、真名和异格检索，防止测试样本与构建字段不一致。

Windows 已完成 release 构建与资源校验，未进行本机窗口交互测试。Android、iOS、macOS 与 Linux 未在本轮构建；浏览器检查不等于触摸设备或全部剧情素材的实机验证。
