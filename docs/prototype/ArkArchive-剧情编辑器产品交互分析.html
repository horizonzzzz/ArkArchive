00一页结论

先给判断，再给证据与路径。

这个编辑器已经完成了「能编」的闭环：四级结构、双来源素材、舞台直编、自动保存、导入导出、官方剧情派生。下一阶段的瓶颈不在指令数量，而在编辑回路的长度和结构的不可见。以剪辑软件为目标，真正值得借的不是轨道，而是四件事：常驻监视器、可定位的播放头、选择集驱动的批量操作、以及交付管线。

配套交互原型：ArkArchive 双端交互原型（分阶段）——桌面与手机两种形态，P0/P1/P2 可在界面中直接切换与定位。原型已按现有应用外壳对齐：桌面左侧为「剧情馆 / 人物档案 / 创作 / 系统设置」，编辑器是「创作」下的一个页面（路由 /editor/:projectId?view=stage|board|script|deliver）；四个「台」是编辑器内部工作区，不与应用导航同级。外部页面仅做位置占位。

形态

从单页三栏，走向四工作区

编排（故事板）/ 演出（舞台+轨道）/ 剧本（对白表格）/ 交付（检查+导出）。上下文跨工作区保持，像 DaVinci 的页面切换，而不是把所有控件塞进一屏。

时间

不做逐帧时间轴，做两级时间

分镜级「叙事序列」可拖动、可缩放；分镜内以「指令 / 停顿点」为刻度的播放头可 scrub。对白没有固定时长，逐帧只会制造假精度。

效率

选择集比按钮更重要

多选、框选、剪贴板、右键菜单、命令面板。剪辑软件的高效来自「选中一批 → 一次改完」，而不是工具栏更长。

能力

结构可视化优先于新指令

故事板、状态泳道、分支图。引擎已支持 decision / warp / label / predicate，缺口在「看不见」，不是「做不到」。

一句话定位：把编辑器从「逐条填指令的表单」升级为「以舞台为中心的演出工作台」——选中即所见，拖动即调整，结构可俯瞰，成品可交付。

本报告不重复 docs/prototype/剧情编辑器优化说明-v0.2.md 已列的 18 项修复（其中大部分已在本分支落地），而是在其「一套数据模型、多种视图」的方向上再往前推一步：给出工作区划分、时间语义、交互范式与功能路线，并标注可直接落代码的位置。

1.2 已经做对的事（应保留）

  • 状态累积模型与引擎一致。分镜不是「时间片段」，而是「一段意图」；这让它天然适配视觉小说的点击推进与分支。
  • 舞台直编 + 方向键微调。背景 / 插图 / 立绘 / 舞台文字都能拖，坐标与检查器双向同步，这是「以画面为中心」的正确起点。
  • 素材双来源与临时加载。PRTS 素材按需读取、不污染剧情缓存；本地素材内容寻址、可校验。
  • 原始指令保真。不认识的指令不丢，能编辑源码；这为分支、演出等高级能力留了后门。
  • 官方剧情派生。改编这一主流创作场景已经打通，冷启动成本远低于从零新建。

1.3 影响交互的关键事实

下面这些不是「感觉」，而是从当前分支代码里读出来的行为。它们决定了哪些优化是低垂果实，哪些需要先改架构。

现象代码位置与机制对用户的真实影响
舞台永远显示分镜末态 editor_stage.dart 的 _rebuild：end = ranges[(scene, beat)].$2，即重放到该分镜全部指令之后 选中第 1 条指令，看到的是第 9 条之后的画面；调位置、调淡入时只能靠猜。这是与剪辑软件「播放头决定画面」最大的落差
试播是模态且自动连播 story_editor_page.dart 的 _preview：Dialog + 每 250 ms advance；只有播放/暂停/重播/下一步 不能边看边改；没有上一句、没有句级 scrub、没有倍速；与正式播放器的句级进度条和历史跳转完全脱节
每次编辑全量重建舞台 EditorStage.didUpdateWidget 比较整个 project 引用；任何指令变化都会触发 100 ms 防抖后的 rebuildBefore 打字时舞台反复闪烁/卡顿；改动越靠前，重建成本越高
保存是整包重写 editor_platform_io.dart：save() 直接 project.export()（含全部 base64 素材） 素材重的作品每停顿一次就写几十 MB；素材越多，编辑越不跟手
窄屏的拖动把手是「装饰」 _commandRows 的 inlineInspector 分支用静态 Icon(Icons.drag_handle)，没有接 ReorderableDragStartListener 手机端指令不能拖，只能走菜单「向前/向后移动」；与桌面手感不一致
作品列表旧在前 _projects 使用 _drafts.values.toList().reversed，而存储层已按修改时间倒序 最新的作品排在最下面，用户每次都要往下找
导入入口重复 工具栏「作品操作」菜单与「我的作品」对话框各有一个导入 入口不一致，违背 v0.2 已定的「统一入口」
校验不可定位 _issues 只渲染文本列表 能看到「第 3 幕 / 分镜 2 / 指令 5：素材缺失」，但没有「前往」；长作品里等于找不到
没有多选与剪贴板 _command 是单个 int；复制只支持单条「复制指令」 批量改台词、整段搬运、跨分镜复用都要重复点选，长作品成本极高
素材选择是模态 _pick 打开 EditorMaterialPicker Dialog，选中即关闭 不能常驻比对、不能拖拽入舞台、不能连续替换多个对象

综合判断：当前瓶颈是「编辑—预览」回路太长（改参数 → 静态末态 → 开模态试播 → 关闭 → 再改），以及「结构—状态」不可见（看不到幕/分镜全貌，也看不到某个背景从哪条指令生效到哪条）。这两个问题都不是加指令能解决的。

03核心判断：借什么，不借什么

视觉小说不是 NLE。照搬时间轴会制造假精度，也会背叛引擎语义。

3.1 三种「时间」不是一回事

剪辑软件的时间

墙钟时间、帧级精度、轨道彼此独立、任意位置可随机访问。观众被动观看。

本引擎的时间

命令序列 + 停顿点（对白 / 等待 / 选项）+ 动画插值（duration）。观众点击推进，状态在指令之间累积。

结论

可以借「空间化」与「随机访问」，不能借「逐帧对齐」与「轨道独立」。时间轴必须换一种刻度。

引擎已经具备两个关键能力，恰好支撑这种改造：

  • StoryEngine.stopPoints：把每条对白/选项/等待变成带说话人、文本、背景、立绘快照的「停顿点」，正式播放器的句级进度条就建立在其上。
  • StoryEngine.seekToCommand(index) / rebuildBefore(index)：可以重放到任意指令位置，这是播放头 scrub 的技术基础。

换句话说，「分镜内的播放头」不是新引擎能力，而是把已有能力接到编辑器的 UI 上。这也是本报告把「选中即预览」列为 P0 第一项的原因。

3.2 可迁移 / 不可迁移清单

应当借

  • 常驻监视器：编辑时画面一直在，参数变化即时反馈
  • 播放头：以停顿点/指令为刻度，选中哪里看哪里
  • 传输控制：上一句 / 播放 / 下一句 / 循环本段 / 倍速
  • 选择集：Shift 连选、Ctrl 点选、框选、区间选择
  • 直接操作：拖动、吸附、参考线、数值气泡
  • 素材箱：常驻、可搜、可拖入、可替换引用
  • 页面式工作区：粗剪 / 精修 / 文本 / 交付各司其职
  • 交付管线：检查清单 → 预览 → 导出 → 版本

不应照搬

  • 逐帧时间轴：对白没有固定时长，帧级只是假精度
  • 多轨自由关键帧：引擎是命令式，无法表达任意曲线
  • 轨道独立混合：状态会被后续指令覆盖，不是并行叠加
  • 波形对位：BGM 是全局状态，不是可裁剪片段
  • 无限层叠：绘制顺序由引擎固定，编辑器不应承诺任意调层
  • 完整 NLE：视频剪辑、调色、绿幕不是本产品目标

设计原则：用「状态泳道」表达并行与覆盖，用「停顿点序列」表达节奏，用「播放头」表达当前位置。三者合起来，才是视觉小说版的「时间轴」。

04产品形态：四工作区

功能继续长，单页三栏一定会拥挤；解法是「同一模型、多工作区」，而不是更多弹窗。

当前所有能力都挤在一个页面：结构、舞台、指令、检查器、试播、素材、校验。结果是每个区域都不够深，且互相打断（开素材要关舞台，开试播要关编辑）。参考 DaVinci 的页面式工作流，建议把桌面端编辑器拆成四个工作区，顶部切换，当前幕/分镜/选中对象/播放头位置跨区保持。

入口与资产治理边界：现网已有的「我的作品」（新建、导入、复制、重命名、调用正式播放器直放）属于进入编辑前的作品管理入口，「作品素材管理」（引用计数、体积预算、清理未引用素材）属于本地上传资产治理弹窗。两者均保留在作品/工具栏层，不与「交付台（单篇出口）」混淆；在第一期未上线常驻素材箱前，不可移除原有素材清理入口。

4.2 移动端形态（做减法，不强求双端四区对等）

手机端不应把桌面三栏压成长列表，也不应把桌面「四工作区切换条」直接叠在「底部应用主导航 + 16:9 监视器」之间（390px 竖屏上固定区会占去过半高度，挤压指令列表）。建议移动端做能力收口，聚焦「监视器 + 传输条 + 指令列表 + 底部属性抽屉」：

单手持机（竖屏 · 主工作态）

  • 主视图即演出台：上方 16:9 监视器，下方固定传输条（上一句 / 播放 / 下一句）与指令列表
  • 轻量副视图：仅保留「分镜切换（卡片横滑）」与「检查与轻导出」两个轻量视图，不强推桌面式多列剧本表格与复杂框选批量
  • 属性与操作：检查器收为底部抽屉（peek / half / full），长按指令进入单手批量选择；舞台支持专注模式与双指缩放

横屏 / 平板

  • 接近桌面双栏：左监视器 + 分镜切换，右结构/指令
  • 检查器作为可滑出的侧抽屉，不永久占宽
  • 保留播放头与传输条；外接键鼠时可启用桌面快捷键与多工作区

形态判断：如果短期内不做四工作区，至少先做「演出台」的完整化——常驻监视器 + 传输条 + 可折叠素材抽屉 + 可折叠检查器。这是投入产出比最高的一步，也为后续工作区留好插槽。

05UI 交互优化方向

七个方向，按「是否缩短编辑回路」排序；D2 是核心，其余围绕它服务。

D1 工作台与面板：让该常驻的常驻

现状：三栏固定宽度（215 / 弹性 / 290），舞台与指令上下分；素材、作品、试播、校验都是模态对话框。用户每换一次任务，就要关闭一个窗口、打开另一个窗口，上下文反复丢失。

目标：面板可折叠、可拖拽分隔、宽度记忆；素材与预设常驻左栏；检查器与问题常驻右栏；模态只保留「必须阻断」的确认。

具体交互

  • 可拖拽分隔条：左右面板与舞台之间可调宽，双击恢复默认；宽度写入本地偏好。
  • 面板停靠：素材选择器支持「固定到左栏」，选中素材后不关闭，可连续替换多个字段。
  • 专注模式：Tab 隐藏左右栏，只留监视器与传输条；再按恢复。
  • 布局预设：「编排 / 演出 / 剧本 / 交付」四个工作区各自记住面板状态，而不是一套布局硬塞。
  • 移动端：检查器改为底部抽屉（三档高度：peek / half / full），不再内联撑高列表。

为什么先做

它不改数据模型、不改引擎，只改容器与状态管理，却是后续「故事板 / 泳道 / 素材箱」能否塞进来的前提。没有可停靠的容器，新视图只能继续做成弹窗，交互债会越滚越大。

落点：story_editor_page.dart 的 build 布局与 _pick / _preview；新增面板状态持久化（宽度、折叠、页签）。

D2 播放头与传输控制：把「试播」变成「监视器」

现状：舞台显示的是分镜末态，不是选中指令的位置；试播是模态 Dialog，250 ms 自动推进，只有播放/暂停/重播/下一步。改一句台词、挪一个立绘，都要「关掉试播 → 改 → 再开」。

目标：把「播放头」引入分镜内部。选中哪条指令，舞台就显示执行到那条指令之后的状态；试播从模态变成常驻监视器，带句级传输控制。

指令 3 后
选中「背景 A」显示背景 A、立绘未入场
指令 7 后
选中「立绘登场」显示 A + 立绘 + 对白
分镜末态
分镜末态（当前行为）所有指令执行完

这是当前最值得做的一项：改动量小（把 end 从「分镜结束」改为「选中指令 + 1」），收益直接——用户终于能「看哪打哪」，而不是改完再开试播猜。

试播的三种形态

  1. 就地监视器（默认）：停靠在舞台位置，播放时右侧检查器仍可改参数，改完立刻看到。
  2. 全屏预览（观看）：隐藏编辑 UI，按真实交互播放（对白等待点击、选项可点），用于验收成片观感。
  3. 提取片段（对比）：只播放当前分镜或选区，用于 A/B 对比修改前后。

播放头刻度

刻度不是秒，而是「停顿点 + 指令」。对白按字数估算宽度，delay 按秒数，动画按 duration；顶部可切换「等宽 / 估时」两种显示。这样既保留节奏感，又不撒谎。

技术落点

editor_stage.dart 的 _rebuild 改为接收 playhead，end = beatStart + playhead + 1；页面把 _command 传下去，分镜切换时重置。播放用 advance，跳转用 seekToCommand，句级导航用 stopPoints。

D3 选择集与批量：让「一次改一批」成为可能

现状：_command 是单值，复制只支持单条，移动只能逐条菜单；没有剪贴板、没有框选、没有混合值检查器。

目标：把「选择」升级为一等公民。剪辑软件的高效不来自功能多，而来自选择集上的批量动作。

选择手势结果随后可做
单击单选，播放头跳转改属性、拖拽
Shift + 单击从锚点到目标的连续区间批量删除 / 移动 / 复制
Ctrl / ⌘ + 单击增减单条跨段组合，批量改字段
行内拖拽框选矩形覆盖的指令批量操作
全选 / 反选当前分镜或当前幕批量检查
舞台框选当前舞台上的多个对象相对移动、对齐、批量改坐标

批量动作

删除、复制、移动、禁用、改字段、替换素材、加标记。检查器对多选显示混合值（如「说话人：多个值」），修改后统一写入。

剪贴板

Ctrl+C / X / V，跨分镜、跨幕、跨作品；内部剪贴板保留指令序列，粘贴到播放头之后。复制时给出「已复制 7 条指令」的轻提示。

右键与命令面板

指令行、分镜卡、舞台对象都提供上下文菜单；Ctrl+K 打开命令面板，搜索「添加立绘 / 替换背景 / 导出视频」等动作，键盘可完成全流程。

D4 舞台直接操作：从「圆点」到「变换框」

现状：每个可拖对象是一个 44 px 圆点，且同屏显示整个分镜的所有把手；没有吸附、没有参考线、没有视图缩放；选中某对象时，其它对象的把手仍在，容易误拖。

目标：「选中什么，就编辑什么」；舞台本身可缩放平移；对齐有辅助，结果可预期。

选择与手柄

  • 默认只显示选中对象的手柄；其它对象显示极淡的可点击轮廓，hover 才显形。
  • 变换框边界：仅具备 width / size 字段的舞台文字（subtitle）提供四角调字号、四边调宽度；立绘、背景、CG 在当前字段模型中无缩放参数，仅提供位置移动框 + 中心线/对齐吸附，不在 UI 上承诺不存在的自由拉伸。
  • 跨分镜继承对象的直编策略：在当前分镜拖动继承自前序分镜的立绘/背景时，不静默失败也不悄悄篡改前序分镜，而是弹出轻量二选一：「跳转到来源指令」或「在当前分镜插入覆盖指令」（并提示影响范围）。
  • 拖动时显示数值气泡（X / Y 或宽 / 字号），松手可点击气泡直接输入；按住 Shift 锁定单轴。

对齐与视图

  • 吸附：舞台中心线、三分线、安全框、其它对象边缘；吸附阈值 6 px，Alt 临时关闭。
  • 对齐按钮：检查器提供左/中/右、上/中/下、水平/垂直居中，一次到位。
  • 视图：50%–200% 缩放，空格 + 拖拽平移，双击适配；缩放只影响视图，不改坐标。
  • 对象列表：舞台左上角浮层列出当前生效的背景、CG、立绘、文字、BGM，点击选中来源指令，一眼看清「现在台上有什么」。

注意边界：引擎不支持任意图层排序、立绘/背景自由缩放与自由旋转（立绘只有 posfrom/posto 与站位，背景仅支持坐标与 screenadapt）。编辑器应显示「层级说明」，但不要提供无法编译成脚本的控件——所有 UI 操作都必须能落成一条合法指令。

D5 结构与导航：让长作品可去、可回、可找

现状：幕用下拉框切换，分镜用横条/列表，指令列表只显示当前分镜；没有面包屑、没有搜索、没有「上次编辑位置」；作品中段之后导航成本明显上升。

结构树（左栏常驻）

  • 作品 → 幕 → 分镜三级可折叠；当前项高亮，滚动自动跟随。
  • 幕/分镜支持拖拽重排、右键菜单（新建、复制、重命名、删除、标记）。
  • 每行显示状态徽标：指令数、警告数、标记颜色、估算时长。
  • 顶部搜索框：按标题、台词、角色、素材 key 过滤；结果直接跳转。

导航与定位

  • 面包屑：作品 / 第 2 幕 / 分镜 7 / 指令 3，每一级可点。
  • 前进后退：Alt+←/→ 在最近编辑位置间跳转，像 IDE 一样。
  • 恢复现场：重新打开作品回到上次的幕/分镜/指令与滚动位置。
  • 标记：颜色 + 备注（待换图 / 待配音 / 审核意见），故事板与结构树都能过滤。
  • 问题定位：校验结果的每一条都可「前往」，并高亮对应指令。

D6 检查器控件：从「表单」到「调参器」

现状：字段是普通文本框/数字框/开关/下拉；音量、淡入淡出、透明度都要手打 0–1 的小数；没有分组、没有重置、没有单位提示；多选时无法编辑。

目标：高频参数用「可拖拽数值 + 滑杆」，低频参数折叠到「高级」，让检查器像剪辑软件的属性面板一样顺手。

D7 反馈与信任：让用户敢改

剪辑软件让人敢大规模修改，是因为「随时可退」。当前只有 60 步撤销和覆盖式自动保存，缺三样东西：看得见的历史、可回退的版本、改动影响的预警。

保存与版本

  • 工具栏常驻「已保存 12:03 / 保存中 / 失败·重试」，失败时红色警示点不消失。
  • 每 5 分钟或每次导出前自动快照，保留最近 10 个；「恢复到此版本」带预览。
  • 导出前强制快照，命名含时间与作品版本号。
  • 打开作品时若检测到上次异常退出，提示「恢复到最近快照」。

历史与影响

  • 撤销历史面板：按时间列出「修改对白 / 移动立绘 / 插入背景」，点击跳转；当前步高亮。
  • 影响预警：修改靠前的背景/立绘时，提示「将影响后续 6 个分镜的画面」，可预览受影响的缩略图。
  • 差异对比：按住 Alt 查看修改前画面，松开回到当前；分镜卡显示「有未确认改动」。
  • 检查清单：错误 / 警告 / 建议三级，逐条「前往」；导出前必须处理错误项。

一句总结：D1 解决「东西放哪」，D2 解决「看哪改哪」，D3–D4 解决「怎么快」，D5 解决「怎么找」，D6 解决「怎么调」，D7 解决「敢不敢改」。七项里 D2 的投入产出比最高，应第一个做。

06功能点优化方向

缺口不在指令数量，而在「结构可视化」与「交付」。以下七条按产品价值排序。

F1 故事板：把「分镜列表」升级为「可粗剪的卡片墙」

这是最接近剪辑软件「素材箱 + 序列缩略图」的视图，也是当前最缺的「全貌感」。

卡片内容

  • 缩略图：该分镜末态（或首句停顿点）渲染，按分镜签名缓存，避免重复重建。
  • 标题、首句台词、指令数、估算时长、警告数、标记颜色。
  • 角标显示「含分支 / 含音频 / 含特效」，一眼识别重演出段。

操作

  • 拖拽重排、跨幕拖拽、框选批量删除/复制/移动。
  • 缩放（小卡/中卡/大卡），按幕分组，按「有警告 / 有标记 / 未完成」过滤。
  • 双击进入演出台并定位到该分镜；右键「在此后插入分镜 / 从此派生副本」。
  • 底部显示全作品估算时长与分镜数，服务「做多长的片子」这个创作决策。

这是本产品区别于普通剪辑软件、也最容易被用户误解的机制：一条背景指令会一直生效，直到被覆盖。当前没有任何视图表达这件事，导致「我只改了第 2 幕的背景，为什么第 3 幕也变了」。

交互

  • 横轴是分镜序列，不是秒；每个色块表示「从某条指令生效，到被覆盖」。
  • 点击色块跳到来源指令；hover 显示素材名、参数、开始/结束位置。
  • 过滤：只看背景、只看某角色、只看音频；支持「只看当前分镜」。
  • 缺失素材/警告用斜纹或红色描边标出，点击直接修复。

配套能力：影响范围与固化

选中一条指令，泳道高亮它影响到的后续区间，并提示「影响 6 个分镜」。提供「在此固化状态」：把当前舞台状态编译成一组显式指令插入，切断对前序的依赖——类似剪辑软件的嵌套序列/渲染并替换，是长作品防连锁修改的关键。

F3 分支与路径状态：引擎已会，只差一张图

引擎已注册 decision、predicate、label、warp、skipnode、theater；编辑器的可视指令表里却没有它们，只能改源码。需注意：当前 StoryEngine 仅支持 decision 产出选择值（_selectedValue）与 predicate(references=...) 过滤，不存在通用脚本变量系统。

阶段 1：只读图

节点 = 分镜/标签，边 = 选项与跳转；点击节点跳转对应分镜；死链、不可达节点、空选项自动标红。

阶段 2：可视化编辑

新增选项、连线、分支条件；生成对应的 decision / predicate / warp / label 指令；与指令列表双向同步。

阶段 3：路径调试

试播时高亮当前路径；展示当前选项值（selectedValue）与各分支 predicate 命中状态；在选项处暂停，手动选分支。

先做只读图 + 跳转，成本低、立刻解决「看不懂」；可视化编辑等分支使用率被验证后再投入，且不引入引擎不支持的通用变量赋值体系。

F4 素材工作流：从「字段里找素材」到「素材上做作品」

当前路径是「先选指令 → 打开字段 → 模态选素材」。剪辑软件的路径是「先浏览素材 → 拖到时间线」。后者更适合探索式创作，也更适合改编（先看官方素材，再决定怎么用）。

素材箱

  • 常驻左栏，按 PRTS / 本地 / 最近 / 收藏 / 未使用分组。
  • 网格/列表切换，虚拟滚动，缩略图懒加载并缓存。
  • 搜索支持角色别名、差分、素材 key；显示尺寸、体积、引用次数。
  • 拖拽：拖到舞台 = 新建背景/CG/立绘指令；拖到字段 = 替换；拖到轨道 = 插入。

引用管理

  • 替换引用：一次替换全作品中的某素材，保留位置/淡入淡出等参数。
  • 定位引用：从素材反查「哪些分镜用了它」，逐条跳转。
  • 缺失修复：列出缺失素材与影响范围，批量重选。
  • 体积预算：显示作品总体积与最大贡献者；导出前提示超限风险。

F5 预设与宏：把重复演出变成资产

改编与连载创作里，大量演出是重复的：立绘淡入、黑场转场、BGM 切换、情绪特写。当前只能复制分镜再改，效率低且容易漏改。

  • 演出片段：选中一段指令 → 存为预设，参数化（角色、表情、时长、背景）；从预设面板拖入任意分镜。
  • 内置预设：角色登场/退场、黑场转场、闪白、震屏、BGM 淡入淡出、情绪特写、双人对话模板。
  • 作品模板：新建时选择「对话戏 / 战斗演出 / 分支示例 / 空白」，生成骨架与示例指令。
  • 宏的边界：预设只生成标准指令，不引入新语法；这样导出脚本仍然可读、可移植。

F6 交付：优先轻量化可传播交付，视频编码后置

当前导出只有「作品 JSON（含素材）」与「纯脚本 TXT」。结合项目跨 Windows / Linux / Android / Web 且无音视频编码依赖的现状，P1 应优先做零编码成本的轻交付，把跨平台视频录制/离屏成片后置到 P2 按需验证。

交付物形态技术路径优先级

交付台还应提供作品元数据：封面、简介、标签、版本号、署名与素材来源说明。这不是装饰——同人作品分发时，素材来源与授权说明是刚需，也能降低 PRTS 素材使用的版权风险。

F7 智能辅助：加速冷启动，而不是替人创作

可以做，但应放在最后，且坚持三条原则：建议而非自动写入、结果可撤销、不破坏离线可用。

  • 文本拆分镜：粘贴纯文本剧本，按对白/旁白自动切成 beat，识别说话人；用户逐条确认。
  • 素材检索：用自然语言描述（「雨夜的城市远景」）在 PRTS 目录里找候选，仍由用户拍板。
  • 台词检查：标点、长度、说话人与立绘是否匹配、连续相同表情等轻量规则，不替代人工润色。
  • 不做：自动生成整段剧情、自动配乐、自动发布。这些会稀释「创作工具」的定位，也带来版权与质量问题。

P1 · 结构能力与桌面高效视图（约 1–2 个月，中风险）

P1-1

故事板视图（桌面卡片墙 + 手机轻量切换）

桌面端卡片墙、缩略图按分镜签名缓存、拖拽重排、框选批量、按幕分组、标记过滤、估算时长；移动端仅保留轻量分镜横滑切换。落点：新增 editor_board.dart，复用引擎渲染。

验收：40 个分镜的作品能在 2 秒内看到全貌；拖拽重排不丢状态；批量删除可一次撤销。

P1-2

状态泳道 + 影响范围 + 固化状态

六类泳道、生效区间、点击跳转、影响高亮；「在此固化」把当前状态编译为显式指令。落点：新增 editor_lanes.dart，静态扫描 commands。

验收：选中背景指令能看到它覆盖的分镜范围；固化后删除前序指令，后续画面不变。

P1-3

素材箱 + 拖拽 + 替换引用

常驻左栏、最近/收藏/未使用、拖到舞台或字段、全作品替换、缺失修复、体积预算（承接并升级原「作品素材管理」弹窗）。落点：拆分 EditorMaterialPicker，新增 editor_bin.dart。

验收：连续替换 5 个背景不需要重复打开对话框；替换后位置与淡入淡出保留。

P1-4

结构树 + 搜索 + 标记

作品/幕/分镜三级树、拖拽排序、面包屑、Alt+←/→、全局搜索（台词/角色/素材/标记）、恢复上次位置。

验收：在 100 个分镜里搜一句台词并跳转 ≤ 3 步；重新打开作品回到上次位置。

P1-5

分层保存 + 自动快照 + 撤销历史面板

结构 JSON 与素材包分层落盘（消除重素材写盘阻塞）；每 5 分钟/导出前快照，保留 10 个；历史操作列表可跳转；异常退出恢复提示。落点：editor_platform_io.dart 增加分层存储、快照目录与轮转。

验收：重素材作品自动保存不阻塞输入；误删分镜后能从快照恢复；历史面板能定位到「移动立绘」那一步。

P1-6

剧本台：对白表格 + 批量替换（桌面优先，适配官方派生）

按幕/分镜列出说话人、台词、表情、状态；行内编辑、筛选、批量替换说话人、导出 TXT/CSV/SRT；双击跳回演出台。移动端不提供大表格，只保留搜索定位。

验收：改编一篇 200 句官方剧情，改 20 句说话人不超过 1 分钟。

P2 · 轻交付拓展与高级能力（季度级，按需评估）

P2-1

分支图 + 路径状态调试

先只读图（节点/边/死链），再可视化编辑，最后选项路径高亮与 selectedValue / predicate 命中状态调试（不引入通用脚本变量系统）。落点：新增 editor_branch_graph.dart，解析 decision/warp/label/predicate。

P2-2

交付深化：Web 交互包 / 预览视频 / 审阅包

在 P1 台本/SRT 与正式播放器直放基础上，优先验证「Web 只读交互包」（复用项目 Web 构建）；实时录制预览 MP4 与离屏逐帧成片因跨平台编码成本高，作为远期探索项；导出前检查清单、素材署名清单与自动快照先行。

P2-3

深层渲染缓存：缩略图持久缓存与关键帧快照

解决超长作品与复杂特效分镜的拖动预览流畅度，建立分镜关键帧状态缓存与缩略图磁盘代理缓存。

P2-4

跨作品素材库 + 智能辅助

全局素材与预设库（去重、迁移、授权提示）；文本拆分镜、素材检索、台词检查，坚持建议式与可撤销。

如果只能做三件事：P0-1 播放头、P0-2 试播停靠、P0-3 选择集。这三项合起来，把「改一句看一次」的回路从分钟级压到秒级，是用户能立刻感知的价值；其余方向都可以在此之后按数据排期。

建议的验证方式

  1. 做可点原型，不写全量代码用 3 个真实分镜做「选中即预览 + 传输条」的可交互原型，验证是否真的降低调参成本。
  2. 选三类任务做对照改编改台词、从零搭 12 个分镜、给旧作品换背景。各找 3–5 名目标用户，记录步骤、时间、误操作。
  3. 看三个信号任务时间是否下降 30% 以上；误操作是否下降；用户是否能在不看说明的情况下说出「我现在看到的是哪一步」。
  4. 再决定结构投入若播放头验证通过，再投入故事板与泳道；否则先修性能与素材链路，避免做了大视图却不好用。

09风险与不做清单

明确边界，比列功能更能保护产品。

9.1 主要风险与缓解

风险触发条件缓解
重建性能每次 seek 都从分镜开头重放；长分镜（50+ 指令）或大图多时，拖动播放头会卡节流 + 关键帧缓存 + 增量 apply；播放头拖动时降级为低分辨率/跳帧预览，松手再精确重建
状态连锁改前序背景/立绘导致后续分镜画面变化，用户以为「改坏了」影响范围高亮 + 差异对比 + 「在此固化」；导出前检查「未显式设置的状态」
视频导出跨平台（Win/Linux/Android/Web）无编码依赖，离屏渲染与音频混音时序复杂P1 先交付台本/SRT、正式播放器直放与 Web 只读包探索；MP4 录制与离屏成片后置 P2 按需验证

功能膨胀故事板、泳道、分支图、剧本台同时塞进单页或强铺到手机竖屏桌面用四工作区隔离、新能力先只读再编辑；手机端仅保留演出台、轻量分镜切换与检查定位
移动端精度手指遮挡、拖动误触、长列表性能专注模式 + 手柄放大 + 步进微调 + 底部抽屉；编辑重活引导到桌面

9.2 明确不做

产品边界

  • 逐帧 NLE、多轨关键帧曲线、视频剪辑与调色
  • 任意图层排序、立绘/背景自由缩放与自由变形（引擎不支持的，不提供控件）
  • 通用脚本变量赋值系统（保留 decision + predicate 引擎模型）
  • 移动端竖屏强铺桌面式四工作区与大型对白表格
  • 云端协作、账号体系、在线素材市场
  • 竖屏成片（舞台固定 16:9；竖屏只是编辑形态）
  • 自动生成整段剧情、自动发布

为什么

这些能力要么与引擎语义冲突（关键帧、图层混合），要么把单机创作工具变成平台（协作、市场），要么稀释「改编与演出」的核心价值。把它们留在边界外，才能把 P0/P1 做深。

10.3 与 v0.2 设计文档的关系

v0.2 解决的是「初版实现够不够用」：对话框溢出、摘要、保存警示、缩略图、拖动把手、作品查看地、官方派生、分层保存等 18 项，属于可用性修复。本报告假设这些修复大部分已落地（当前分支确实如此），讨论的是产品形态与效率上限：工作区、时间语义、选择集、结构可视化、交付。两者不冲突，前者是后者的地基。

建议的下一步：先做 P0-1 与 P0-2 的可点原型（不改数据模型），用 3 个真实分镜验证「选中即预览」是否降低调参成本；同时埋点记录「选中→看到画面」「换背景→试看」的步数与耗时。数据通过后，再投入故事板与泳道——这两块是产品形态的分水岭，值得一次做对。
