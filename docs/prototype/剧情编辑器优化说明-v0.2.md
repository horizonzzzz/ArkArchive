# 剧情编辑器 v0.2 优化说明

> 配套文档：[剧情编辑器产品设计.html](./剧情编辑器产品设计.html)（v0.2，2026-11-22）
> 范围：**本次仅修订产品设计原型文档，未改动任何 Flutter 实现代码**（初版实现保持在 `feat/story-editer` 分支 `2f490d1` 提交）。
> 日期：2026-11-22

## 一、背景与结论

初版（M0）已按 v0.1 设计模型落地：作品 → 幕 → 分镜 → 指令四级编辑、舞台拖动、素材双来源（PRTS + 本地上传）、试播、自动保存、导入导出。

对初版做了一轮 UX / 产品走查，结论：

- **骨架方向正确**：分镜模型、状态累积语义、临时资源不污染剧情缓存、原始指令保真、原子写保存，全部保留不动。
- **交互完成度不足**：18 项问题需要修订——P0 7 项（其中 3 项来自实际使用直接确认）、P1 6 项（其中 2 项已拍板方案）、P2 5 项。
- **两条主链路缺失**：作品没有「查看地」（不能正式播放）、官方剧情不能派生创作。用户已拍板补齐。

全部修订已写入产品设计原型 v0.2，落点索引见[第六节](#六落点索引)。

## 二、P0 体验修复（7 项）

| # | 问题（初版现状） | v0.2 修订 |
|---|---|---|
| 1 | 手机端三个对话框固定像素宽度：素材选择器 560px、作品列表 400px、检查结果 460px。390px 宽手机上内容区仅约 310px，**三个对话框全部横向溢出 150~250px**，「选背景」这一核心操作在主投放平台上不可用 | 全部对话框改为 `宽度 = min(设计上限, 可用宽度 − 32px)`、高度同理的自适应约束；手机上优先底部抽屉形态；窄屏进入回归验收 |

## 三、P1 产品结构补强（6 项）

### 已拍板的两项

**1. 我的作品查看地（用户拍板：要）**
- 问题：作品只能在编辑器内小窗试播，导出物也只能回到编辑器导入——创作闭环的终点缺失。
- 方案：「我的作品」页为消费端。作品行内「播放」进入**正式播放器**全片观看（复用现有 StoryPlayer，不写观看进度、不与原版断点混淆）；试播控制条「全屏」共用同一链路。作品页同时承担行内管理（播放 / 编辑 / 重命名 / 复制 / 删除）与修改时间展示。

**2. 官方剧情派生（用户拍板：要）**
- 问题：不支持导入已存在的官方剧情，同人改编这一主流创作场景缺席。
- 方案：剧情馆条目菜单新增「派生到创作」：读取该篇脚本 → 按对白切分分镜 → 高级指令保真保留 → 打开编辑器。素材沿用原版 key，试播与播放按需从 PRTS 临时加载；离线时明确提示不可用，不静默黑屏；原版脚本与缓存不被修改。

### 其余四项（按推荐方案）

**3. 高级指令可编辑 + 粘贴脚本导入**
- 问题：导入作品中的 decision / warp / interlude 等指令只读，连改选项文案都做不到。
- 方案：结构化字段与「指令源码」双向切换，直接编辑源码，保存时逐条解析校验（每条恰好对应一条指令），失败就地标红保留原文；新建作品支持直接粘贴脚本文本。
- 理由：引擎本就支持 decision，缺口只在「改不了」。源码编辑成本最低且覆盖全部高级指令；可视化分支编辑器成本高，留 M2。

**4. 素材体系补齐**
- 问题：素材只增不减（无删除入口，作品文件随垃圾素材膨胀）；角色差分 key `amiya#3$2` 不可读；列表静默截断 500 条。
- 方案：新增作品素材面板（缩略图 / 引用计数 / 删除 / 体积分布，未引用可一键清理）；差分显示「角色 · 别名 / 表情 N」，原始 key 退居副标题；截断时尾部固定提示。
- 理由：作品级面板 + 内容哈希去重先解决「删不掉、看不懂、膨胀」三个痛点；跨作品个人素材库涉及全局状态，后置 M4。

**5. 增量重建 + 分层保存**
- 问题：任何编辑（含改台词）都触发舞台全量重建，打字时舞台反复闪烁；自动保存每次全量重写「结构 + 全部素材字节」，素材重的作品每停顿一次重写几十 MB。
- 方案：两刀切——①「舞台签名」：仅影响画面状态的指令变化才触发重建，对白文本编辑不再重建；②草稿分两层：结构文件高频写，素材文件仅在素材集合指纹变化时重写（key 由内容 SHA-256 构成，指纹相同即内容相同）。旧版单文件草稿自动迁移。
- 理由：都是纯内部优化、用户可感知（不闪烁、不卡顿、省 IO），不改变数据模型，风险低。

**6. 草稿管理可发现**
- 问题：删除 / 重命名必须先打开该作品；列表只显示「N 幕」，无修改时间。
- 方案：作品行内操作 + 最近修改时间展示，不新增页面。

## 四、P2 打磨项（5 项）

| # | 问题 | 修订 |
|---|---|---|
| 1 | 试播只有「下一步」：无自动播放 / 暂停 / 重播 / 加载进度；警告只能看不能定位；点试播窗外遮罩即误关 | 控制条补齐全部控制；准备阶段显示「已加载 x/y 个资源」；警告条目带「前往」直接跳到对应幕 / 分镜 / 指令；退出必须显式点按 |
| 2 | 舞台只有悬浮圆点，无对象轮廓；特效位置只能手填数字；无键盘微调 | 选中立绘 / 舞台文字显示轮廓框；特效把手可拖（原点 640,360，y 向上）；方向键微调 1px、Shift ×10，与检查器数值双向同步 |
| 3 | 无桌面快捷键；指令只能尾部追加；窄屏展开的行内检查器没有任何收起方式 | Ctrl+Z / Ctrl+Shift+Z 全局撤销重做（一次连续输入合并为一步，消除「框内字段级撤销 vs 工具栏全局撤销」的双栈分裂）；指令「在此之后插入」；再点已选中指令即收起 |
| 4 | 添加指令菜单 14 项平铺无分组无说明；「隐藏对白框」命名反直觉；导入入口重复两处；分镜删除后新增会重名 | 菜单按「对白 / 画面 / 音频 / 演出」分组并附一句说明；改称「清除对白框」；导入统一在「我的作品」页；分镜编号取未占用值 |
| 5 | 关键列表与菜单无语义标签；拖动无键盘替代路径；工具按钮只靠 tooltip | 指令 / 分镜行输出「类型 + 摘要 + 序号」语义标签；方向键微调即无鼠标路径；工具按钮补语义标签 |

## 五、暂缓项与理由

| 项 | 暂缓理由 |
|---|---|
| decision / label 可视化分支编辑器 | 引擎已支持、编辑缺口已由源码编辑兜底；可视化编辑器成本高、使用频率待验证，按 v0.1 分期留 M2，先量化长尾 |
| 跨作品个人素材库 | 需要全局素材状态与迁移；先以作品为单位 + 内容哈希去重，重复上传已自动合并，M4 视使用情况决定 |
| 草稿打开时的素材惰性加载 | 牵连素材内存模型与预览/导出链路，改动面大；分层保存已消除高频写压力，打开耗时集中在「多草稿 + 重素材」场景，先观察再决定 |
| 竖屏成片 | 维持 v0.1 决策：舞台固定 16:9（1280×720），竖屏只是编辑界面形态；需求强烈再单独立项 |
| 背景 / 插图的轮廓框 | 背景是全屏层、插图带自由变换，轮廓框语义有限；保持圆点把手 + 实时坐标即可（立绘与舞台文字已给轮廓） |
| 时间轴 / 运镜编辑 | 维持 v0.1 分期（M2），不影响本批修复 |
