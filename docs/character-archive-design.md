# 人物档案 · 产品设计

> 状态：P0.1 构建工具与 P0.2 数据验收已完成；客户端人物列表、详情与回放正在分阶段接入
> 首版实现调整：随应用附带完整人物文本快照，图片按需联网并共享缓存；暂不依赖远程 manifest 服务。下文的远程更新、人物链接与完整图片下载方案保留为后续设计。2026-11-10 数据收录 1,055 位人物，覆盖 2,061 篇目录剧情；具体口径与限制见[构建与验收记录](character-index-build.md)。
> 范围：v1（MVP）与后续分期  
> 关联模块：剧情馆、播放器、离线缓存、PRTS 数据管线

阶段实施记录与复现命令见 [人物档案数据构建](character-index-build.md)。P0.1 产物用于验证数据，不代表下文的生产数据契约或客户端功能已完成。

## 0. 结论先行

| 决策点 | 建议 |
| --- | --- |
| 入口 | 新增独立 Tab「人物档案」，排在「剧情馆」之后 |
| 收录范围 | 可操作干员 + PRTS「剧情角色一览」中的主要人物 |
| 人物粒度 | 人物级；官方 patch 关系直接归并，异格同体由人工 `form_merge.json` 明确归并，不按姓名子串推断 |
| 数据方式 | 构建期生成索引，客户端按需下载详情；不在手机端扫描全量脚本 |
| 详情内容 | 立绘、档案文本、出场剧情、每幕 3 条台词节选 |
| 台词跳转 | 播放器「档案回放模式」，定位到台词但不写观看进度 |
| 剧透保护 | 默认折叠未观看剧情的台词与深层档案，可一键显示全部 |
| 打包边界 | 只打包 UI 与人物索引种子；详情、立绘、剧情脚本现下载 |
| 多立绘 | 用 `arts[]` 区分卡片图/头图/画廊图，不为每张立绘建人物卡 |
| 角色类型 | 干员与剧情角色共用列表，但字段、筛选、详情分区明确区分 |
| 数据托管 | 先用 `data` 分支 + jsDelivr，后续与语音包一起迁对象存储/CDN |

最大的风险不是 UI，而是「说话人 → 人物」的身份归并：剧情脚本里只有显示名，没有稳定的角色 ID。抽样 41 篇脚本中，427 个说话人名只有 117 个能精确匹配干员或 PRTS 剧情角色，Top 20 未匹配名的台词量已占带名台词的约 14%。因此，别名表是 MVP 的关键路径，不是可选优化。

## 1. 产品定义

### 1.1 一句话

一个以「人物」为中心的资料库：看立绘、读档案、找出场剧情，并跳到那一句台词。

### 1.2 目标

- 让用户在剧情之外，也能按人物浏览整个故事库。
- 把「这个人说过什么、在哪一幕说过」变成可检索、可跳转的体验。
- 复用现有播放器、缓存与 PRTS 数据管线，不引入账号和后端服务。
- 区分「游戏角色」与「非游戏角色」的资料组织方式，而不是把两类条目混成一张表。

### 1.3 非目标

- 不做角色关系图、时间线、语音台词库、AI 角色对话。
- 不做全量台词全文搜索（v1 只做人物维度的台词定位）。
- 不做用户共创、评论、打分。
- 不做皮肤全收集（v1 只做基础立绘与精英二立绘）。
- 不试图收录所有路人角色；v1 只收有资料价值的主要人物。

## 2. 用户场景

1. **看完一幕，想查刚才那个人是谁**  
   打开人物档案，搜名字或代号，进入详情看简介与立绘。

2. **喜欢某个干员，想看他/她所有出场**  
   进入干员详情，按主线/活动/故事集/干员密录浏览出场剧情，展开某一幕看台词节选。

3. **想回顾一句名台词**  
   在人物详情的台词节选中点「在剧情中查看」，播放器直接定位到那一句，前后可继续播放。

4. **怕剧透**  
   默认只展开已观看剧情的台词；深层档案资料折叠；需要时手动「显示全部（含剧透）」。

5. **离线**  
   已下载的人物索引、详情和看过的立绘可离线浏览；未缓存的详情提示联网加载。

## 3. 信息架构

```text
底部导航 / 桌面侧栏
├── 剧情馆
├── 人物档案            ← 新增
│   ├── 人物列表（搜索 / 筛选 / 排序）
│   └── 人物详情
│       ├── 档案
│       ├── 立绘
│       ├── 出场剧情
│       │   ├── 台词节选
│       │   └── 该幕全部台词
│       └── 全屏立绘查看
├── 离线与缓存
└── 系统设置
```

- 人物档案作为 `IndexedStack` 的第 2 页，与现有三个页面同级。
- 人物详情使用独立路由，返回后保留列表的搜索、筛选、滚动位置。
- 移动端底部导航共 4 项，建议使用短标签：`剧情 / 人物 / 缓存 / 设置`；桌面侧栏保留全称：`剧情馆 / 人物档案 / 离线与缓存 / 系统设置`。
- 图标建议：`Icons.badge_outlined`（档案/身份卡），与现有线性图标风格一致。

## 4. 页面设计

### 4.1 人物列表

```text
┌ 人物档案 ────────────────────────────────────────────────┐
│ 人物档案                                   [剧透保护 开]  │
│ 已收录约 553 位人物 · 档案数据更新于 2026-11-10             │
│                                                          │
│ [搜索人物、代号或英文名…]                                 │
│ [全部] [干员] [剧情角色]      [职业▾] [阵营▾] [排序▾]    │
│                                                          │
│ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐            │
│ │ 头像 │ │ 头像 │ │ 头像 │ │ 头像 │ │ 头像 │            │
│ │ 阿米娅│ │ 银灰 │ │ 凯尔希│ │ 霜星 │ │ 特蕾西娅│        │
│ │术师 5★│ │近卫 6★│ │剧情角色│ │剧情角色│ │剧情角色│      │
│ │42幕 1286句│ │28幕 903句│ │…│ │…│ │…│                 │
│ └──────┘ └──────┘ └──────┘ └──────┘ └──────┘            │
└──────────────────────────────────────────────────────────┘
```

**顶部**

- 标题：`人物档案`。
- 副标题：`已收录 N 位人物 · 档案数据更新于 YYYY-MM-DD`。
- 右侧开关：`剧透保护`，默认开启；关闭时需二次确认「将显示未观看剧情的台词」。

**搜索**

- 占位文案：`搜索人物、代号或英文名`。
- 匹配字段：人物名、别名、英文名、阵营、职业、CV（若后续补充）。
- 支持全角/半角括号归一化：`阿米娅（近卫）` 与 `阿米娅(近卫)` 等价。
- 搜索排序：精确名 > 别名 > 前缀 > 子串；同分按出场次数降序。
- v1 不引入拼音库；如需拼音搜索，在构建期把全拼/首字母写入索引（P1）。

**筛选**

- 一级：`全部 / 干员 / 剧情角色`，默认「全部」。
- 二级（仅干员）：职业（8 类）、阵营（20 个国家/地区 + 组织）、星级（1–6）。
- 移动端二级筛选放入底部抽屉；桌面端使用下拉多选。
- 避免把筛选做成一排过多的 chip；按记忆中的设计偏好，复杂多选项收进下拉/抽屉。

**排序**

- 默认：`出场次数` 降序（同分按台词数、首次出场）。
- 可选：`首次出场` 升序、`名字`、`星级` 降序（剧情角色排在后面）。
- 「首次出场」使用剧情目录的全局顺序，而不是字符串或日期。

**卡片**

- 桌面：`SliverGrid`，`maxCrossAxisExtent ≈ 220`，一行 4–6 张；移动端 2 列。
- 卡片比例约 3:4；图片区域占上方 70%，信息区占下方 30%。
- 干员卡片：
  - 方形头像（`头像_<名>.png` 缩略图），顶部左侧职业文字标签，顶部右侧星级。
  - 名称 1–2 行；阵营小字；底部 `N 幕 · N 句`，数字用 Bender 字体。
- 剧情角色卡片：
  - AVG 立绘裁切（优先按 `faceRect` 裁脸，否则 `Alignment.topCenter` + `BoxFit.cover`）。
  - `剧情角色` 标签；首次出场篇章；`N 幕 · N 句`。
- 无立绘：使用姓名首字/首词的几何占位块，不显示破图。
- 悬停/聚焦：边框变为 `AppColors.borderLight`，不改变尺寸；键盘可聚焦、回车打开。
- 卡片整体是一个 `InkWell`，点击进入详情；不在卡片上放播放按钮，避免误触。

**状态**

- 首次加载：6–10 个骨架卡片，不使用全屏转圈。
- 索引加载失败：`人物档案暂时无法读取` + `重试` + `先看剧情`。
- 搜索无结果：`没有找到匹配的人物` + `清除筛选`。
- 无网络且无缓存：同上，文案改为 `需要联网加载一次人物档案`。

**头部**

- 桌面：左侧立绘（约 40% 宽，3:4 或 2:3），右侧信息；最大内容宽 1200。
- 移动：顶部横幅立绘（约 16:9 裁切）+ 下方信息；名称与标签浮在渐变上。
- 名称：22–28px，粗体；英文名/称号小字；别名以 `ArchiveTag` 形式最多显示 3 个，超出 `+N`。
- 标签：`干员`/`剧情角色`、职业、星级、阵营；剧情角色不显示职业/星级。
- 统计：`出场 N 幕`、`台词 N 句`、`首次登场 篇章`。数字用 Bender。
- 主操作：`从首次出场播放`（进入播放器档案回放模式）。
- 次操作：`查看全部立绘`（滚动到立绘区/打开画廊）。
- 更多菜单（右上）：`检查档案更新`、`复制人物链接`（P1）、`反馈问题`。

**形态切换**

- 仅当人物有多个形态时显示，例如阿米娅的 `术师 / 近卫 / 医疗`。
- 形态 chip 切换立绘、职业、星级与档案文本；出场剧情不随形态变化（人物级聚合）。
- 官方 `char_patch_table.json` 的形态关系直接归并；其他异格同体（如 W/维什戴尔）只按人工 `form_merge.json` 合并，不能由同名或括号后缀推断。

**档案区**

- 干员：
  - 从 `handbook_info_table.json` 解析 `基础档案` 的 `【键】值`，渲染为两列键值表。
  - `综合体检测试` 以标签 + 等级文本展示；v1 不做雷达图。
  - `客观履历` 直接显示。
  - `档案资料一~四`、`晋升记录` 默认折叠，按钮文案 `展开档案资料（含剧透）`。
  - 跳过标题为 `？？？` 或正文全为 `？` 的条目。
  - `unLockType = PATCH/FAVOR/AWAKE` 的条目视为剧透内容，默认折叠。
- 剧情角色：
  - 显示 PRTS 页面「简介」，默认按剧透内容折叠；用户主动查看后，正文以 4 行截断并提供 `展开`。
  - 若有 `npcDict` 数据，补充英文名、CV、阵营。
  - 显示 `资料出处`：PRTS 页面「出处」列的篇章名，注明「PRTS 记载」。
- 页脚：`档案文本与立绘来自 PRTS / 明日方舟游戏资料；本应用为非官方同人项目。`

**立绘区**

- 横向画廊，卡片比例 3:4；桌面 3–4 张可见，移动 2.2 张可见。
- 干员：精英零、精英二；有皮肤时 P1 追加。
- 剧情角色：AVG 立绘的多个版本（Ver.1/Ver.2）。
- 每张图下方小字：`精英二` / `默认服装` / `剧情立绘 1`。
- 点击进入全屏查看。

**出场剧情区**

- 顶部统计：`共 N 幕 · N 句`；右侧筛选 `全部/主线/活动/故事集/干员密录/其他`；`只看已看` 开关。
- 按「分类 → 篇章」分组，组头显示 `篇章名 · N 幕 / N 句`，默认可折叠。
- 每一幕一行：`关卡代号 + 剧情名 + 行动前/后`，右侧 `N 句` 和观看状态标签（`已看`/`进行中`/`未看`）。
- 展开后显示最多 3 条台词节选；每条：说话人、台词、`第 N 句`、播放图标。
- 底部 `查看全部 N 句` → 该幕全部台词页。
- 无台词：`暂无台词记录；该人物可能只在剧情中露面。`

### 4.3 全屏立绘

- 黑底 `InteractiveViewer`，支持双指/滚轮缩放、拖动、双击放大。
- 左右滑动切换同组立绘；顶部显示人物名 + 图片说明，右上关闭。
- 加载中显示低清缩略图或骨架；失败显示 `立绘加载失败` + 重试。
- 不在全屏页写入任何状态；关闭回到详情原位置。

### 4.4 台词节选与跳转

**节选规则（v1，确定性）**

每幕最多 3 条：

1. 该人物在本幕的第一句台词。
2. 该人物在本幕的最后一句台词。
3. 排除已选首句和末句后，中间台词中最长的一句（长度相同时取靠后的一条）；最终按原剧情顺序展示。

少于 3 条则全部显示。节选区标题标注 `节选`，避免用户误以为这是全部台词。
P1 可加入人工/模型挑选的「名场面」覆盖规则。

**全部台词页**

- 标题：`<人物名> · <剧情名>`。
- 副标题：`本幕共 N 句台词`。
- 列表：每句一行，显示 `第 N 句`、说话人、文本、播放按钮。
- 顶部提供 `从头播放本幕`。
- 台词从该幕脚本实时加载并按人物/别名过滤，不随索引下发全量文本。

**跳转播放器**

- 新增 `initialCommandIndex` 与 `archiveMode` 两个可选参数。
- `archiveMode = true`：不写观看进度，不更新「已看」状态；顶部显示 `档案回放 · 不记录进度`，提供 `继续观看`（退出档案模式，开始正常记录）。
- 播放器就绪后调用 `engine.seekToCommand(commandIndex)`；成功后暂停在目标台词。
- 若目标 command 不是停顿点或 seek 失败：回退到从头播放，并提示 `无法定位到该台词，已从开头播放`。
- 若脚本已变化（`scriptHash` 不一致）：先按 `line` 查找，再按台词文本查找；仍失败则回退开头。
- 分支限制：seek 会按「第一个未禁用选项」重放；若目标台词前有分支，可能进入默认分支。v1 在 UI 不承诺「完全还原当时分支」，P1 可存 trace 精确恢复。

### 4.5 状态与空态

| 场景 | 展示 |
| --- | --- |
| 索引首次加载 | 骨架卡片 + 顶部 `正在读取人物档案…` |
| 索引加载失败、有缓存 | 使用缓存，顶部细条提示 `当前为离线档案` |
| 索引加载失败、无缓存 | 空态：`人物档案暂时无法读取` + 重试 + 返回剧情馆 |
| 详情加载失败、有索引 | 显示卡片级信息 + `详细档案加载失败` + 重试 |
| 详情加载失败、无网络 | `该人物的详细档案需要联网加载一次` |
| 搜索无结果 | `没有找到匹配的人物` + 清除筛选 |
| 无立绘 | 姓名首字占位块 + `暂无立绘` |
| 无台词 | `暂无台词记录` |
| 剧透保护开启、剧情未看 | 台词区折叠为 `含剧透 · 点击显示`，不自动加载全文 |

## 5. 人物模型与收录规则

### 5.1 两类人物

| 维度 | 干员（游戏角色） | 剧情角色（非游戏角色） |
| --- | --- | --- |
| 判定 | 可操作单位 | PRTS「剧情角色一览」中的非可操作人物 |
| 主数据源 | `character_table` + `handbook_info_table` + `skin_table` | PRTS 剧情角色页 + `handbook.npcDict`（少量） |
| 立绘 | 官方头像、精英零/二立绘 | AVG 剧情立绘（`Avg_*`） |
| 档案 | 基础档案、客观履历、档案资料 | 简介、出处、英文名/CV（若有） |
| 卡片标签 | `干员` + 职业 + 星级 + 阵营 | `剧情角色` + 首次出场篇章 |
| 详情重点 | 档案资料、形态、皮肤（P1） | 剧情立绘、简介、出场 |
| 筛选 | 职业/阵营/星级 | 无职业/星级筛选 |

### 5.2 人物 / 形态 / 别名

- **人物（Person）**：档案卡的单位。一个人物只有一张卡。
- **形态（Form）**：同一人物的干员单位或立绘版本，例如阿米娅的术师/近卫/医疗、W 与维什戴尔。详情页用 chip 切换。
- **别名（Alias）**：剧情脚本中的显示名、真名、称号、英文名。别名用于台词归属与搜索，不等于新建人物卡。

「同一个人」有三种不同的关系，必须分开处理：

| 关系 | 定义 | 例子 | 处理 |
| --- | --- | --- | --- |
| A. 同名+括号形态 | 同一 charId 家族，游戏内即互斥形态 | 阿米娅(近卫)、阿米娅(医疗) | 直接合并，`forms` 按游戏内顺序 |
| B. 异格同体 | **不同 charId 的独立干员，但在剧情中是同一个人** | 维什戴尔之于 W、耀骑士临光之于临光、浊心斯卡蒂之于斯卡蒂、凛御银灰之于银灰 | 合并为一人，各 charId 挂 `forms` |
| C. 真名/代号/称号 | 同一干员的不同称呼（并非另一单位） | 恩希欧迪斯之于银灰，莉泽尔之于复奏 | 只做别名，不改形态 |

**异格（关系 B）的处理：人工表为唯一数据源**

异格产出频率极低（一年仅数个），不值得维护通用自动匹配规则；统一走人工 `form_merge.json`，构建期**绝不自动合并**：

1. **初始表一次性导出**：建 `form_merge.json` 时可跑一次扫描辅助——「英文名 `Base the XXX` 模式且 `Base` 恰为另一可玩干员英文名」在当前 438 干员上命中 28 对、零误报（如 `SilverAsh the Reignfrost` → 凛御银灰 ↔ 银灰；含多对一：陈 → 赤刃明霄陈 / 假日威龙陈）；另加 MH 联动 3 对（火龙S黑角、雷狼龙S空爆、麒麟R夜刀）与点号变体（凯尔希·思衡托）；再人工补完全异名对（W/维什戴尔——`Wiš'adel` 不含 the，规则扫不到）。合计约 33 对。这些只是**起草工具**，登记前仍逐对人工确认。
2. **此后完全人工**：新版本构建时，脚本把「疑似新异格」候选（the 模式、中文名包含等）写进报告提示，人工确认后手工登记，年均也就几条。
3. **合并语义**：标准体为主 form，异格按实装时间排在之后；台词/出场按人物级聚合（脚本中「W」与「维什戴尔」的台词都归到同一张卡）；形态切换时立绘/职业/星级随之变化，出场剧情不变。
4. **反向保护**：名字包含但非同体的（阿→阿斯卡纶、林→杜林、红→红豆）明确**不合并**——它们是不同的人；任何包含关系只做报告候选提示。

v1 合并规则（更新）：

1. 同名 + 括号后缀视为同一人物：`阿米娅`、`阿米娅(近卫)`、`阿米娅(医疗)`。
2. 异格同体完全走人工 `form_merge.json`（初始约 33 对，含 W/维什戴尔；构建期不自动合并）。
3. 真名/称号（C）只做别名：`恩希欧迪斯` 的台词归银灰，但不给银灰加形态。
4. 其他跨名合并默认不做，留给人工表。

### 5.3 收录与排除

**收录**

- 全部可操作干员（约 438 个单位；阿米娅三形态合并后约 436 位人物）。
- PRTS「剧情角色一览」中的主要人物。页面共 121 条，排除 `占位符`、`？？？`、`XX 的父母/父亲/母亲` 等群体或占位条目后约 117 位；其中 112 位有 AVG 立绘。
- 有档案文本或至少 1 句台词的条目才进入列表；两者都没有的条目不展示。

**排除**

- 纯路人称呼：`天灾信使`、`菜贩`、`征战骑士`、`首领`、`商队头领`、`赏金猎人` 等。它们进入 `character_blocklist`，不建卡。
- 未在 PRTS 剧情角色页、也没有官方档案的次要说话人：v1 不建卡，但写入构建报告的 `unmatched_speakers.csv`，作为 P1 扩充候选。
- 同名但明显不同的人：不自动合并，交给人工表。

**为什么 v1 不收录所有说话人**

抽样中 427 个说话人名，约 73% 无法精确匹配现有干员/剧情角色；其中大量是路人称呼、临时身份、未揭示代号。全部建卡会产生数百张没有立绘、没有简介、名字还是剧透的卡片，反而降低档案质量。v1 先保证「有资料价值的主要人物」完整，P1 再按台词量/立绘可用性逐步扩充。

### 5.4 排序与搜索

- 默认排序：出场幕数降序 → 台词数降序 → 首次出场升序。
- 次要排序：首次出场升序、名字、星级降序。
- 「首次出场」按剧情目录全局顺序，不按发布日期猜测。
- 搜索权重：精确名 100，别名 80，英文名 70，前缀 60，子串 40，阵营/职业 20；同分按出场次数。
- 搜索输入防抖 150ms；列表客户端过滤，不请求网络。

### 5.5 多立绘模型

不要把人物压成一张 `image` 字段。一个人物可以有多张立绘，按用途分成三类：

| 角色 | 用途 | 选图规则 |
| --- | --- | --- |
| `card` | 列表卡片 | 干员用方形头像；剧情角色用 AVG 立绘裁脸；都没有则姓名占位 |
| `hero` | 详情头部 | 干员优先精英二，其次精英零，再次头像；剧情角色默认 AVG 立绘 |
| `gallery` | 立绘画廊 | 该人物所有有效立绘，按形态/类型分组 |

**干员的剧情立绘（storyArt）**

已实装干员除了标准立绘，还有大量**剧情限定立绘**——遗尘漫步中凯尔希有 `char_003_kaltsn07/08/09` 三种旧形象，巴别塔时期 W 亦有专属 AVG 形象。这些图不在 `skin_table`，而在 AVG 资源表里，需要单独通路：

- 数据源：`assets/avg/character.json`（AVG 立绘注册表）。把 key 与干员 charId 核心段匹配（`char_003_kaltsn07_1` ↔ `char_003_kalts`）的条目归并到该干员名下，`kind: "storyArt"`、`group: "剧情"`。
- 排除基础形象：`char_003_kalts_1`（AVG 中的日常形象）不进「剧情」组，它是人物的基础 AVG 形态，剧情角色卡才用作主图；与干员标准立绘重复度高的可去重。
- `spoiler: true` 默认折叠：剧情立绘往往携带身份/时期剧透（凯尔希 WD 形象直接剧透遗尘漫步结局），剧透保护开启时缩略图遮罩，点击显示。
- 标签带出场篇章：`label: "剧情形象 · 遗尘漫步"`（篇章从引用该 key 的故事脚本反查）；同一形象出现在多篇时的取最早篇章。
- 判定归属不明的 AVG key（如 `avg_npc_*` 中实际对应干员的）写人工表兜底；构建报告列出「疑似干员 AVG 形象未归并」。

**通用规则**

- 一张立绘只属于一个人物/形态，不为每张立绘新建人物卡。
- `role` 只决定默认展示位置，不限制它出现在画廊；`card`/`hero` 图也可以出现在画廊。
- `formId` 把异格立绘挂到形态；人物级画廊按形态分组。
- `group` 用于画廊分区：`默认`、`精英`、`皮肤`、`剧情`、`表情`。
- `order` 决定排序；`spoiler` 标记剧透图（精英二、皮肤、异格、剧情形象），剧透保护开启时折叠或模糊。
- 同一文件的不同分辨率只保留一个条目；不同文件名但内容相同的，用文件哈希去重。
- 构建期探测候选链，只写有效 URL；失败写入 `art_404.csv`。

**卡片图选择**

- 干员：`头像_<名>.png` 的 160–240px 缩略图，方形、稳定、辨识度最高。
- 剧情角色：`Avg_<key>_1.png` 或 `MediaCatalog.character(key)` 的 body + `faceRect`；裁脸失败则顶部居中裁切。
- 没有立绘：姓名首字/首词占位块。
- 允许 `cardArtId` 人工覆盖特殊情况，例如头像缺失、或某张 AVG 图不适合裁切。

**头图选择**

- 干员：精英二 → 精英零 → 头像；剧透保护开启且精英二标记 `spoiler` 时，头图用精英零。
- 剧情角色：默认 AVG body；有多个版本时用 Ver.1/默认版本，其他进画廊。
- 允许 `heroArtId` 人工覆盖。

**画廊选择**

- 干员：精英零、精英二、皮肤（P1）、半身像（若有）。
- 剧情角色：剧情立绘 Ver.1/Ver.2、表情差分（P1）。
- 每组首图与当前头图一致，避免用户点进画廊找不到头图。
- 多形态人物按形态分组：例如阿米娅的 `术师 / 近卫 / 医疗`，每组独立画廊。
- NPC 的 AVG 资源常是同一身体 + 多个表情差分（face overlay）。v1 只展示身体版本，不把每个表情做成一张画廊图；P1 可做「表情切换」。

**加载与缓存**

- 列表只加载 `card` 缩略图；详情头图加载 800px；全屏才加载原图。
- 缩略图与原图分开缓存；全屏预取左右相邻图。
- 图片解码加 `cacheWidth`/`cacheHeight`，避免把 2K 原图解码进列表内存。

### 5.6 已实装与剧情角色的边界

先统一术语：

- **可操作干员**：游戏里已实装、可编队/可培养的单位。社区常说的「已实装角色」在本设计里落到这一类。
- **剧情角色**：只在剧情中出现、没有可操作单位的角色（NPC）。
- **「已实装」不等于「用户已拥有」**：本应用没有账号/干员仓库，不做「拥有」判断。

| 维度 | 可操作干员 | 剧情角色 |
| --- | --- | --- |
| 判定 | `character_table` 可获取，且职业不是 `TOKEN/TRAP/NONE` | PRTS 剧情角色页 / 有 AVG 立绘 / `npcDict` |
| 稳定 ID | `charId`（如 `char_002_amiya`） | PRTS 页面 slug（如 `npc:weiyw`） |
| 基础字段 | 职业、星级、阵营、英文名；CV 可 P1 补 | 英文名/CV/阵营仅部分有 |
| 档案 | `handbook` 基础档案/客观履历/档案资料 | PRTS 简介 + 资料出处 |
| 立绘 | 头像、精英零/二、皮肤（P1）、剧情形象 storyArt | AVG 剧情立绘、表情差分（P1） |
| 卡片 | 职业 + 星级 + 阵营 | `剧情角色` + 首次出场篇章 |
| 详情 | 形态切换（含异格 forms）、档案资料、皮肤、剧情形象 | 简介、资料出处、剧情立绘 |
| 筛选 | 职业/阵营/星级 | 无职业/星级筛选 |
| 出场统计 | 精确名匹配为主 | 别名/称号匹配为主，覆盖率更低 |
| 数据完整度 | 高 | 中/低，允许「资料有限」 |
| 生命周期 | 随版本新增/调整 | 可能后续实装为干员 |

**产品呈现**

- 共用一个列表 + 类型筛选（全部/干员/剧情角色），不拆成两个 Tab；搜索能同时命中两类。
- 卡片用标签区分；详情用不同分区；「星级」排序下剧情角色排在干员之后。
- 不要把剧情角色标成「干员」，也不要用干员的职业/星级字段填空；缺失就隐藏。
- 剧情角色详情显示「资料出处：PRTS 剧情角色一览」，并注明「资料有限」。

**分类与生命周期规则**

1. 能匹配到可操作单位（`charId` 且 `isNotObtainable=false`，职业非 `TOKEN/TRAP/NONE`）→ 干员。
2. 否则在 PRTS 剧情角色页或有 AVG 立绘 → 剧情角色。
3. 两边都命中（例如 Sharp）：以可操作状态为准；若只是同名 NPC，按剧情角色。
4. 剧情角色后续实装为干员：构建数据把 `kind` 改为 `operator`，保留旧 `npc` id 作为 redirect/alias；旧链接跳到新卡，不产生两张卡。
5. 干员异格：复用官方 patch 形态关系，其他同体关系由人工 `form_merge.json` 归并；真名仅做别名，不用姓名子串推断身份。

## 6. 数据来源与可行性

### 6.1 PRTS 资源盘点

| 资源 | 实测情况 | 在本功能中的用途 |
| --- | --- | --- |
| 干员一览（PRTS 页面） | 页面可用于人工核对 | 不作为运行时解析源；用同源静态表替代 |
| `character_table.json` | 1437 条，含职业/星级/阵营/英文名 | 干员基础元数据 |
| `skin_table.json` | 含 `avatarId` / `illustId` / 皮肤名 | 头像、立绘、P1 皮肤 |
| `handbook_info_table.json` | 448 条；438/438 可玩干员覆盖；每人数个档案章节 | 干员档案文本 |
| `charId.js`（PRTS charinfo） | 469 个「显示名 → charId」；补全异格名称 | 干员显示名与异格映射 |
| `story_review_table.json` | 2061 条剧情，全部有 `storyTxt` | 出场剧情的篇章/关卡/顺序 |
| 剧情脚本 | 抽样 41 篇，平均约 35KB；全量估算约 72MB | 说话人、台词、节选、跳转位置 |
| 剧情角色一览（PRTS 页面） | 121 条；112 条有 AVG 立绘；简介平均 147 字 | 非游戏角色的名单、简介、出处、立绘 |

### 6.2 实测数据

- **剧情规模**：2061 条剧情条目，全部有脚本路径；抽样 41 篇平均 35KB，全量约 72MB。不能在手机端每次扫描。
- **说话人**：41 篇样本共 8,329 条带名台词、427 个唯一说话人名；精确匹配干员 104 个、剧情角色 13 个，合计 117 个（27%）。Top 20 未匹配名的台词量约占 14%。
- **干员档案**：`handbook_info_table` 覆盖全部 438 个可玩干员；阿米娅等异格在 `character_table` 中可能缺名称/表项，需要 `charId.js` 补全。
- **剧情角色**：121 条中 112 条有 AVG 立绘；9 条无立绘（占位符、家属、群体条目等）。排除占位/群体后约 117 位。
- **图片规则**：PRTS 媒体路径可由文件名 MD5 计算；头像/立绘/半身像命名稳定，但少数异格立绘存在 404，需要构建期探测。

### 6.3 资源地址规则（已验证）

PRTS 媒体文件路径：

```text
https://media.prts.wiki/{md5(filename)[0]}/{md5(filename)[0:2]}/{urlencode(filename)}
```

已验证 200 的命名：

- `头像_阿米娅.png`
- `立绘_阿米娅_1.png`
- `立绘_阿米娅_2.png`
- `半身像_阿米娅_1.png`
- `头像_阿米娅(近卫).png`

已验证的例外：

- `立绘_阿米娅(近卫)_1.png` → 404
- `立绘_阿米娅(近卫)_2.png` → 200
- `立绘_阿米娅(医疗)_1.png` → 404
- `立绘_阿米娅(医疗)_2.png` → 200

结论：不要假设 `_1` 一定存在。构建期为每个形态探测候选链：

```text
立绘_<名>_1.png
→ 立绘_<名>_2.png
→ 立绘_<baseName>_1.png
→ 头像_<名>.png（兜底）
```

剧情角色的 AVG 立绘有两种可用地址：

- `https://torappu.prts.wiki/assets/avg/characters/<key>/<key>.png`
- `https://media.prts.wiki/{md5}/Avg_<key>_1.png`

两者均验证 200。客户端优先复用现有 `MediaCatalog.character(key)`，可拿到 body/face/faceRect，卡片裁脸更自然。

缩略图：`https://media.prts.wiki/thumb/{hash}/{filename}/{width}px-{filename}`。列表用 160–240px，详情用 800–1024px，避免直接下载原图。

### 6.4 关键风险：说话人识别

剧情脚本的对白格式是：

```text
[name="阿米娅"]   博士，请下令。
```

只有显示名，没有稳定的角色 ID。实测中的典型问题：

| 脚本显示名 | 实际人物 | 处理方式 |
| --- | --- | --- |
| `莉泽尔` | 复奏（char_4031_liesel） | 别名表 |
| `艾利奥特` | 异客（char_472_pasngr） | 别名表 |
| `恩希欧迪斯` | 银灰（char_172_svrash） | 别名表 |
| `瓦列里奥` | 圣徒瓦列里奥 | Wiki 重定向 + 别名表 |
| `天灾信使` / `菜贩` / `征战骑士` | 路人 | blocklist |
| `？？？` | 未揭示身份 | 不归属，避免剧透 |

处理策略：

1. **精确名**：干员名、剧情角色名。
2. **括号归一化**：`阿米娅(近卫)` → `阿米娅`。
3. **Wiki 重定向**：批量调用 `action=query&redirects=1`，可解决少量正式别名。
4. **档案文本反查**：在干员档案/NPC 简介里搜说话人名；只在高置信度且唯一时自动采纳。
5. **人工别名表**：Top 200 未匹配名逐个确认；这是 MVP 前必须完成的数据工作。
6. **不强行归属**：宁可少收录，也不要把台词挂到错误人物上。

`[Character(name="char_xxx")]` 资源 key 可以作为辅助证据，但 v1 不以它为主：NPC 的 `avg_npc_*` key 与显示名不是一一对应，舞台焦点逻辑也更复杂。

## 7. 数据管线

### 7.1 构建流程

```text
1. 下载 character_table / skin_table / handbook_info_table / story_review_table
2. 下载 charId.js（显示名 → charId）
3. 获取剧情角色一览 HTML（PRTS API；失败时用仓库内快照）
4. 下载 2061 篇剧情脚本（并发 8，带重试与缓存）
5. 解析脚本：按 [name="..."] 提取台词与 commandIndex
6. 按别名表归属到人物；聚合出场幕数、台词数、节选
7. 生成 index.json + details/<id>.json + report.json
8. 探测立绘 URL，生成可用立绘列表；404 写入报告
9. 发布 manifest.json（版本、校验和、详情 base）
```

建议命令：

```bash
dart run tool/character_index/build.dart \
  --stories-cache .cache/stories \
  --npc-page tool/data/npc_page.html \
  --out build/characters
```

构建耗时估算（本机/CI）：

- 下载 2061 篇脚本：72MB，8 并发约 3–8 分钟，取决于网络。
- 解析与生成：< 30 秒。
- 输出：索引约 1–2MB；详情合计约 10–15MB；压缩后显著更小。

### 7.4 别名表与质量报告

建议仓库内维护：

```text
tool/data/
  character_aliases.json     # 显示名 → 人物 id（真名/称号/代号，关系 C）
  character_blocklist.txt    # 路人/群体称呼
  form_merge.json            # 异格同体人工表（关系 B 规则覆盖不到的）
  npc_page.html              # PRTS 页面快照（CI 访问失败时使用）
```

`character_aliases.json` 示例：

```json
{
  "恩希欧迪斯": "op:char_172_svrash",
  "莉泽尔": "op:char_4031_liesel",
  "艾利奥特": "op:char_472_pasngr",
  "瓦列里奥": "npc:圣徒瓦列里奥"
}
```

`form_merge.json` 示例（异格同体唯一数据源，人工维护；初始表可由一次性扫描起草：英文 the 模式 28 对 + MH 联动 3 对 + 点号变体 1 对 + 完全异名人工补录，合计约 33 对）：

```json
[
  { "base": "char_113_cqbw", "alt": "char_1035_wisdel", "altName": "维什戴尔" },
  { "base": "char_010_chen", "alt": "char_XXXX_chen2", "altName": "赤刃明霄陈" },
  { "base": "char_010_chen", "alt": "char_XXXX_chen3", "altName": "假日威龙陈" }
]
```

构建报告：

- `report.json`：人物数、干员/NPC 数、异格合并对数、台词归属率、立绘 404 数、未匹配说话人数、干员剧情立绘归并数、疑似新异格候选（仅提示）。
- `unmatched_speakers.csv`：`name, lineCount, sampleStory, sampleText, candidate, confidence`。
- `npc_excluded.csv`：被排除的占位/群体条目。
- `art_404.csv`：立绘候选链全部失败的形态。
- `story_art_unmatched.csv`：疑似对应干员但未归并的 AVG 立绘 key。

质量门槛建议：

- 干员立绘覆盖率 ≥ 95%。
- Top 200 说话人的台词归属率 ≥ 90%。
- 全量带名台词归属率 ≥ 70%（剩余主要是路人和未揭示身份）。
- 任何人物不得出现「同一句台词挂到两个人」；如有，构建失败。
- 异格合并表约为 33 对且全部人工确认；阿斯卡纶/杜林等同名子串永不入表；新版本构建只输出候选提示、不自动合并。

### 7.5 托管与版本

| 方案 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- |
| `data` 分支 + jsDelivr | 免费、CDN、按文件取详情 | 国内访问不稳定；仓库历史会变大 | v1 快速落地 |
| GitHub Release 资产 | 与现有发布流程一致 | 按文件下载不便；更新要发版 | 备选 |
| 对象存储 + CDN | 稳定、可与语音包共用、版本管理清晰 | 需要运维与少量费用 | 推荐长期 |

建议：

- v1 用独立 `data` 分支（孤儿分支，每次构建强制推送，避免历史膨胀）+ jsDelivr；GitHub raw 作为回退。
- 索引与详情 URL 带版本：`.../characters/2026-11-10/index.json`、`.../2026-11-10/details/op_char_002_amiya.json`。
- `manifest.json` 放固定地址，内容指向当前版本；客户端每次打开人物档案时最多每 24 小时检查一次，手动菜单可强制检查。
- 缓存：索引常驻共享缓存；详情按版本缓存；立绘按 URL 缓存。清理剧情缓存时保留索引与 manifest，详情可清可重下。

## 8. 客户端设计

### 8.1 模块拆分

建议新增独立目录，避免继续把 `story_launcher.dart` 撑大：

```text
lib/characters/
  data/
    character_models.dart        # Person / Form / Appearance / Snippet
    character_repository.dart    # manifest、index、detail 加载与缓存
    character_media.dart         # PRTS 图片 URL、缩略图、MD5 路径
    character_filters.dart       # 搜索/筛选/排序
  ui/
    character_archive_page.dart  # 列表页
    character_card.dart
    character_detail_page.dart
    character_profile_section.dart
    character_art_gallery.dart
    character_art_viewer.dart
    character_story_lines_page.dart
```

集成点：

- `story_launcher.dart`：新增导航项、`IndexedStack` 第 2 页、`CharacterRepository` 实例。
- `asset_store.dart`：新增 `watchedStories` 读取/写入；`clearCache` 的 `keep` 集合加入人物索引/manifest。
- `story_player.dart`：新增 `initialCommandIndex`、`archiveMode`；在 `_prepare` 完成后 seek。
- `story_engine.dart`：复用现有 `seekToCommand`；不改分支/重放逻辑。
- `playback_progress.dart`：不改结构；新增独立的已看集合，避免把「已看完」误判为「未看」。

### 8.2 缓存与离线

- 索引/manifest：`AssetStore.loadShared` + `writeCache`，归入共享层；清理剧情缓存时保留。
- 详情：按 `id + version` 缓存；未缓存时进入详情先显示索引信息，再异步加载详情。
- 立绘：缩略图与原图分别缓存；列表只加载缩略图，详情/全屏才加载原图。
- 离线策略：
  - 有索引：列表可用；详情/立绘未缓存时显示占位与「需要联网加载」。
  - 无索引：显示空态与重试；不阻塞剧情馆、缓存、设置。
- 缓存清理：设置页「清空素材缓存」保留人物索引与 manifest；详情/立绘可被清理，之后按需重下。P1 可在设置页增加「人物档案缓存」单独清理项。

### 8.3 剧透保护与观看记录

- 新增 `watchedStories` 集合（独立于 `playbackProgresses`）：
  - 正常播放到结束时，`onProgress(null)` 的同时标记该 `path` 为已看。
  - 已有进度但未看完：状态为「进行中」，不算已看。
  - P1 在剧情条目菜单提供「标记为已看/未看」，方便在别处看过剧情的用户。
- 剧透保护开启时：
  - 未看剧情的台词节选折叠为 `含剧透 · 点击显示`。
  - 干员深层档案（`PATCH/FAVOR/AWAKE`）折叠。
  - 剧情角色简介超过 4 行时折叠。
  - 不隐藏人物卡本身；人物名/头像的剧透风险由用户自行承担，避免列表因保护而不可用。
- 剧透保护关闭时：全部展开，顶部显示一次性提示 `已显示全部剧情内容`。
- 无任何观看记录时：不隐藏，只在详情顶部显示 `尚无观看记录，以下内容可能含剧透`。

### 8.4 播放器跳转

- `StoryPlayer` 新增：
  ```dart
  final int? initialCommandIndex;
  final bool archiveMode;
  ```
- `archiveMode = true` 时不传 `onProgress`，并隐藏/弱化「保存进度」相关提示；顶部显示 `档案回放` 标识。
- `initialCommandIndex` 在 `_prepare()` 完成后执行：
  1. 校验 `commandIndex` 对应 command 是停顿点。
  2. 调用 `engine.seekToCommand(index)`。
  3. 成功则暂停在目标台词；失败则 `engine.start()` 从头播放并提示。
- 「继续观看」：把 `archiveMode` 置 false，恢复 `onProgress` 回调，从当前位置开始记录。
- 返回：`Navigator.pop` 回详情；不写进度、不标记已看。
- 脚本变化：详情里存 `scriptHash`；进入播放器后与当前脚本指纹比对，不一致则按 `line`/文本回退定位。

### 8.5 性能

- 列表：`SliverGrid` 懒加载；`cacheExtent` 控制在 600–800；卡片只解码缩略图。
- 图片：内存 LRU 上限（如 80 张缩略图）；离开页面时释放大图。
- 索引：约 1–2MB；解析一次后常驻内存；搜索/筛选在内存完成。
- 详情：单个 10–30KB；进入详情时异步加载，不阻塞头部渲染。
- 台词全量：只在用户点「查看全部」时加载该幕脚本；加载后按人物过滤，不缓存全量到索引。
- 列表滚动目标 60fps；移动端 2 列、桌面 4–6 列。

### 8.6 打包与下载边界

原则：**包内只放「没有它页面打不开」和「很小、很稳定」的东西；内容型数据全部现下载并缓存。**

| 内容 | 打包进 App | 首次使用现下载 | 缓存 | 说明 |
| --- | --- | --- | --- | --- |
| UI 字体、图标、纹理、着色器 | 是 | 否 | — | 现有资源，不随人物数据变化 |
| 人物索引种子 `seed_index.json` | 是（建议） | 否 | 共享层 | 约 1–2MB 原始大小，压缩后更小；保证首次打开/离线也有列表 |
| 远程 `manifest.json` | 可选兜底 | 是 | 共享层 | 版本、详情 base、校验和；每次打开最多 24 小时检查一次 |
| 完整 `index.json` | 种子即完整索引 | 有新版本时 | 共享层 | 远程版本覆盖种子；不重复打包另一份 |
| 人物详情 `details/<id>.json` | 否 | 首次进详情 | 共享层 | 单人约 10–30KB；全部约 5–15MB，不值得打包 |
| 干员档案文本 | 否 | 随详情 | 随详情 | 已在详情 JSON 内，不单独请求 |
| 剧情角色简介/出处 | 否 | 随详情 | 随详情 | 同上 |
| 卡片缩略图 | 否 | 列表进入视口时 | 图片缓存 | 160–240px，约 10–30KB/张 |
| 详情头图/画廊图 | 否 | 进入详情/画廊时 | 图片缓存 | 800px 左右，约 100–500KB/张 |
| 全屏原图 | 否 | 打开全屏时 | 可选 | 原图可能 1MB+；按需加载、预取相邻 |
| 剧情脚本与剧情素材 | 否 | 现有按篇缓存 | 现有缓存 | 人物档案的「全部台词」复用 `StoryRepository.loadEntry` |
| 别名表 / blocklist | 否 | 否 | — | 构建期使用，结果烘焙进索引；客户端不需要 |

**索引种子**

- 建议把完整索引作为种子打包，而不是只打包卡片级数据：索引本身只有 1–2MB，换来「首次打开秒出列表、离线可浏览、远程失败有兜底」。
- 种子索引随 App 版本更新；启动后仍会检查远程 manifest，有新版本就替换缓存。
- 如果非常在意包体，可退化为「只打包卡片级种子（<500KB）+ 远程完整索引」；代价是首次打开要等网络，且离线只有名字没有统计。
- 种子索引内不放档案正文、台词节选、图片二进制，避免包体膨胀和剧透文本随包分发。

**详情与图片**

- 进入人物详情先渲染索引里的卡片信息（名字、标签、统计），详情 JSON 异步加载；不要整页转圈等详情。
- 卡片只加载缩略图；头图/画廊加载中等尺寸；全屏才加载原图。三级尺寸分开缓存。
- 图片缓存按 URL 去重；同一张立绘在卡片、头图、画廊命中同一缓存条目。
- 详情按 `id + indexVersion` 缓存；索引升级后旧详情自然失效，不读取过期数据。

**首次打开与离线**

1. 有缓存索引：立即显示缓存；后台检查 manifest。
2. 无缓存索引：立即显示包内种子；后台拉取远程索引。
3. 远程失败：继续用种子/缓存，顶部细条提示 `当前为离线档案`。
4. 详情/图片未缓存且无网络：显示卡片信息 + `该人物的详细档案需要联网加载一次` / 图片占位。
5. 剧情已缓存：该幕的「全部台词」和跳转可离线使用；剧情素材沿用现有缓存规则。

**清理缓存**

- `clearCache` 的 `keep` 集合加入人物索引、manifest、种子版本标记；清空剧情缓存不会让人物列表消失。
- 人物详情与图片属于可再下载数据，可以清理；P1 在设置页增加「人物档案缓存」独立条目（显示占用、单独清理）。
- 不建议把人物索引放进「按剧情删除」的目录；它是全局共享数据。

**包体预算**

- 种子索引：约 1–2MB 原始大小；APK/IPA 压缩后通常 < 1MB。
- 不打包任何立绘/头像；不为「首次打开好看」预置图片。
- P1 可选「下载全部人物档案」离线包：索引 + 详情 + 缩略图（不含原图），约 30–60MB，适合经常离线阅读的用户；不作为 MVP。

## 12. 风险清单

| 风险 | 影响 | 缓解 |

## 附录 B：详情页信息优先级

1. 第一眼：这个人是谁（立绘、名字、英文名、阵营/职业）。
2. 第二眼：他/她出场多不多（幕数、台词数、首次登场）。
3. 第三眼：我想看哪一幕（按篇章分组、已看/未看）。
4. 第四眼：这一句是什么（节选、跳转）。
5. 深度内容：档案资料、全部台词、皮肤（折叠/次级入口）。

这个顺序决定默认展开项：档案只展开基础档案与客观履历；出场剧情默认展开第一组；节选默认显示 3 条；其余折叠。

## 附录 C：与现有功能的边界

- **剧情馆**：按篇章/关卡组织，解决「这一章讲什么」；人物档案按人物组织，解决「这个人出现在哪」。
- **播放器**：人物档案只负责定位，不复制播放器 UI；跳转复用现有 seek 与舞台重放。
- **离线缓存**：人物索引是共享层数据，不随单篇剧情删除；人物详情/立绘按需缓存，可单独清理。
- **搜索**：剧情馆搜索篇章/关卡；人物档案搜索人物/别名；两者不合并，避免结果混杂。P1 可考虑全局搜索入口，但不在 v1。
