PRD 明日方舟双端剧情播放器标准化重构产品设计说明书

版本： v1.0.0 (Release-Ready Spec) 撰写角色： 移动端/客户端双端产品经理 & 体验设计师 产品形态： Flutter 跨平台 (Android / iOS / Windows / macOS / Web)

1. 产品背景、定位与核心痛点

当前工程已具备核心 AVG 引擎解析（DSL 解析器、分发器、图层渲染和音频播放）。然而，原首页仅通过临时平铺列表展示部分关卡，缺乏标准视听产品应有的层级大纲、批量缓存管理与音频/播放配置能力。

核心产品定位： 一款免登录、离线可用、忠于原作演出、极简克制的明日方舟全剧情播放与归档终端。
端形态 核心交互场景 屏幕方向标准 导航结构
移动端 (Phone) 单手通勤浏览、利用零散时间查阅剧情大纲、预先批量下载章节、沉浸式播放 主界面强制竖屏 (Portrait)；点击播放后强制横屏 (Landscape) 底部 3 项 Tab 导航 + 章节下钻折叠 + 底部抽屉批量操作栏
桌面客户端 (Desktop) 大屏沉浸阅读、剧本研读、考据、批量全量归档备份素材 全局沉浸横屏 (Landscape)，支持窗口化与无边框全屏 左侧固定边栏 Tab + 左右分栏（大纲列表 + 关卡网格）

2. 海量剧情信息架构 (IA) 与 PRTS 数据源对齐方案

《明日方舟》全服沉淀剧情节点已超 3,000+。针对数据源抓取自 https://prts.wiki/w/剧情一览 的工程现实，本设计专门解决了“Wiki 结构与游戏客户端分类不一致”的核心矛盾。

💡 为什么不需要、也不应该机械复刻游戏内的“插曲 / 别传”二元划分？
游戏内将活动强行拆分为“插曲”和“别传”，本质是受制于游戏内的数值养成、掉落物、干员赠送与常驻复刻机制，与剧情体验本身并无直接关联。而在 PRTS Wiki 的《剧情一览》页面中，维基团队早已沉淀了一套更加纯粹、规整的分类模型：
  • 主线剧情一览表 (Table 0)：按章节由浅入深（黑暗时代至相变临界），附带序曲与分支。
  • 活动剧情一览表 (Table 1)：包含 支线（56+ 大型活动，即别传与插曲）、剧情（21+ 故事集微型故事）、集成战略（肉鸽剧情）、生息演算（沙盒故事）与 四月辑录（愚人节活动）。
产品决策：直接以 PRTS 既有的天然数据结构作为骨架，进行极低维护成本的“语义级映射”，既杜绝了维护额外分类映射表的风险，又为用户提供了更符合阅读习惯的层级索引。

3. 关卡选择与离线缓存系统设计

由于全量素材达数十 GB，必须遵循“按需预加载”与“批量自主缓存”策略。针对“能否获取到每个剧情资源大小”的工程现实，本设计制定了严谨的落地规范。

🔍 剧情资源大小的工程可获取性与 UI 展示准则：
  • 能否直接获取？不能。 PRTS 剧情索引 story_review_table.json 及维基大纲页仅包含文本元数据（剧情名称、关卡代号、脚本相对路径），完全不包含音频、立绘、背景图片的体积字段。
  • 能否预先准确计算？代价极高。 必须先向服务器发起 HTTP 请求拉取对应的 .txt 脚本，逐行解析 [background]、[charslot]、[playmusic] 命令，合并 MediaCatalog 计算依赖 URI 集合，并对每个未下载的资源发起 HEAD 请求读取 Content-Length。对上千个剧情关卡，若在大纲列表初始化时这样做会导致严重的网络风暴与明显卡顿。
  • UI 展示准则（优雅降级）：
    1. 未下载前：列表不展示虚假或高成本的 MB 大小。仅展示清爽的状态徽标：未缓存、✓ 已离线 或 缓存中。
    2. 何时能展示？仅在“用户点击关卡”或“进入勾选”后按需异步预估，或在“已下载完成”后直接按本地 FileCache 实际落盘体积（stat.size）显示精确大小。
底层存储原则（复用既有 AssetStore 架构）： 所有下载的多媒体素材采用 SHA-256 内容寻址哈希去重。多章节共用的干员立绘（如凯尔希、阿米娅）与公共 BGM 仅在本地持久化一份，批量下载时自动去重并计算实际增量体积。
功能模块 移动端交互表现 桌面端交互表现 异常处理与兜底
选择模式 点击右上角【批量管理】唤起复选框；长按任一关卡直接触发批量多选态。 表头常驻【全选本章】复选框，每行有关联 Checkbox，支持 Shift 连选。 已离线条目默认仍可勾选（支持批量重新校验或批量删除）。
缓存进度感知 (批量) 关卡卡片转为 缓存中 (带旋转 Spinner)；底部浮出批量进度条（展示 已缓存 3/8 幕 · 3.8 MB/s）。 选中行状态徽标联动显示旋转 Spinner；顶部工具栏同步展示并发下载数与完成率。 断网时保留断点，恢复联网后支持一键【重试失败项】。
在线点播缓冲 (单幕) 点击未缓存关卡 ▶ 弹出流式缓冲加载浮层（显示正在下载的资源名、进度百分比 0~100%），预载完毕后平滑旋转进入横屏播放。 弹出居中 Loading 弹层，显示依赖项加载计数与进度条，缓冲完毕后直接启动全屏演出。 单个图片/音效 404 时记录 warning 并跳过，不阻断剧情播放。

DESIGN SPEC 《明日方舟》视觉设计与交互工程规范 (Design System Spec)

规范版本： v1.0 (Token-Driven Spec) 核心参考： Mooncell PRTS-Design · ak-ui · 腾讯游戏学堂 UX 分析 存储位置： docs/DESIGN.md

1. 设计哲学：后现代机能风与瑞士平面排版

业界俗称的“舟味”，其本质为黑白为体、青为用的高对比工业终端质感。界面严禁滥用大圆角和彩色杂乱气泡，统一保持硬朗直线、微倒角与战术警示标。

四大视觉基石：
  • 黑白终端底色：碳素黑与暗冷灰构成 4 级表面层级（#0a0d12 至 #1f2633）；
  • 克制语义强调：科技青（#00e5ff）为主动作与聚焦，警戒黄（#f6c344）为活动副标签，信号红（#ff5252）仅用于危险删除；
  • 直角与 45° 战术切角：采用 0~4px 直角/微圆角或 BeveledRectangleBorder 切角，杜绝过度圆滑；
  • 大写工业字标与伴生副标：中文思源黑体，西文与数字强制 DIN / 等宽，并排输出大写英文（如 EPISODE 14 / 慈悲灯塔）。

2. 动效节奏与交互曲线 (Snappy Motion)

交互场景 持续时间 缓动曲线 (Easing) 具体表现
